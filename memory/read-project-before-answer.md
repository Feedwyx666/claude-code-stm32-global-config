**条件：仅当当前工作目录被识别为工程文件夹时执行**（如含 `.uvprojx` / `.sln` / `package.json` / `CMakeLists.txt` 等工程文件的目录，或用户明确表示正在做某个项目的目录）。

在工程文件夹中回答用户问题前，**必须先完整通读用户编辑过的工程文件**（除只读库以外的全部 `.c/.h` / `.py` / `.ts` 等），再下结论，不靠直觉与经验。

**Why:** 2026-08-06 用户在 `G:\Claude CLI\TIM定时中断` 调试 OLED 乱码时，我多次仅凭对中断的直觉判断"TIM2 会打断 I2C 导致乱码"，没有先通读工程。用户点破"可是我不加 tim 中断就没有这些问题"，并要求先完整读工程再回答。通读后才发现真正变化是 main.c 主循环加了 `OLED_ShowNum(2,1,Num,5)` 高频刷 OLED（TIM2 中断本身完全不碰 SCL/SDA），此前的判断错误。

**How to apply:**
- 判断当前目录是否为工程文件夹（见条件）。是 → 回答前先 `Glob` 列出工程源码文件，再 Read 完这些非库文件，回答时说明已通读哪些文件。
- 非工程文件夹（桌面/根目录/临时目录等）→ 不强制，按具体问题查阅所需文件即可。
- 涉及 `Library/`、`Start/` 等只读库文件无需通读，按需查阅。
- 关联 [[context-by-cwd]]（工程/非工程判断）、[[tim-study-plan]]。
