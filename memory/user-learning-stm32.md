用户的交流目的是**学习 STM32 嵌入式开发**，而不是单纯要一个修改结果。

**Why:** 用户明确说「我与你交流的目的是学习stm32嵌入式开发」。
**How to apply:**
- 回答问题时侧重**解释原理**（为什么这样、底层机制），不只是给结论或改代码。
- 用户提出方案时（如「在中断里刷新OLED是不是就行」），先分析这个想法对不对、为什么，再谈是否修改。
- 代码示例尽量配注释说明原理。
- 参见 [[confirm-before-edits]]、[[context-by-cwd]]。
